# PE32 for Win x86 🪟🧩

This document explains the 32-bit Windows executable format used by BrainFudger's `win-x86` target.

## Big Picture

A minimal PE32 executable in this project has:

1. a DOS header area
2. a PE signature
3. a COFF file header
4. a PE32 optional header
5. three section headers
6. three sections:
   - `.text` for code
   - `.idata` for imports
   - `.data` for runtime data

## Architecture

- machine type: `0x014C`
- execution model: 32-bit x86
- loader style: Windows PE loader

## DOS Header

PE files still begin with an `MZ` DOS header.

Minimal strategy used here:

- write `MZ`
- zero-fill most DOS legacy fields
- set `e_lfanew` to `0x80`
- pad until offset `0x80`

Windows uses `e_lfanew` to find the PE signature.

## PE Signature And COFF Header

At `e_lfanew`, write:

```text
50 45 00 00   ; PE\0\0
```

Then the COFF file header:

- `Machine = 0x014C`
- `NumberOfSections = 3`
- `SizeOfOptionalHeader = 0xE0`
- executable characteristics appropriate for a simple image

## Optional Header Essentials

Critical fields for a hand-built x86 PE32:

- `Magic = 0x10B`
- `AddressOfEntryPoint = RVA of .text start`
- `BaseOfCode = RVA of .text`
- `BaseOfData = RVA of first data section`
- `ImageBase = preferred load address`
- `SectionAlignment = 0x1000`
- `FileAlignment = 0x200`
- `SizeOfImage = end of highest section rounded to section alignment`
- `SizeOfHeaders = header block rounded to file alignment`
- `Subsystem = 3` for Windows CUI
- import directory RVA and size
- IAT RVA and size

## Sections In BrainFudger's x86 PE

### `.text`

Contains:

- process startup
- `GetStdHandle` calls
- Brainfuck translation
- error handling paths
- exit path

### `.idata`

Contains:

- import descriptor
- import lookup table
- import address table
- DLL name
- hint/name entries for imported functions

### `.data`

Contains:

- standard handle storage
- tape buffer
- tape end label
- `io_result`
- error strings

## RVA vs File Offset

- file offset: where bytes live on disk
- RVA: where bytes live in memory relative to image base

The loader maps each section so:

```text
virtual address = image base + RVA
```

## Import Table Layout

The x86 target imports four functions from `KERNEL32.dll`:

- `GetStdHandle`
- `ReadFile`
- `WriteFile`
- `ExitProcess`

Minimal import structure:

1. `IMAGE_IMPORT_DESCRIPTOR`
2. import lookup table
3. import address table
4. DLL name string
5. hint/name records
6. null terminators

Each x86 thunk entry here is 32 bits.

## Code Generation Shape

The emitted program does:

1. call `GetStdHandle` three times for stdin, stdout, and stderr
2. store returned handles in `.data`
3. set up register pointers:
   - `EBX` = current tape cell
   - `ESI` = tape start
   - `EDI` = tape end
4. emit translated Brainfuck operations
5. call `ExitProcess`

### I/O Calls

Output uses:

```text
WriteFile(stdout_handle, EBX, 1, &io_result, 0)
```

Input uses:

```text
ReadFile(stdin_handle, EBX, 1, &io_result, 0)
```

If `ReadFile` reports failure or zero bytes read, the current cell is zeroed.

## Patching Strategy

The x86 assembler records two patch kinds:

- `Relative32`
- `Absolute32`

Use `Relative32` for internal branches and jumps.

Use `Absolute32` for:

- loading addresses of data labels
- indirect calls through the IAT
- absolute pointers embedded in instructions

For relative jumps:

```text
displacement = target_rva - next_instruction_rva
```

For absolute references in this emitter:

```text
encoded_value = image_base + target_rva
```

## Section Math

The writer uses:

- file alignment: `0x200`
- section alignment: `0x1000`

Workflow:

1. compute total header size
2. round headers to file alignment
3. assign each section `PointerToRawData`
4. assign each section `VirtualAddress` starting at `0x1000`
5. round raw sizes to file alignment
6. round virtual sizes for image-size math
7. compute `SizeOfImage`

## Hand-Build Checklist ✅

1. write DOS header with `e_lfanew`
2. write PE signature
3. write COFF header for x86
4. write PE32 optional header
5. write 16 data-directory entries
6. write three section headers
7. emit `.text`, `.idata`, and `.data`
8. patch import-section label references
9. patch `.text` references against final RVAs
10. pad each section to file alignment

## Common Failure Modes

- wrong `Machine` field
- wrong optional-header magic
- wrong import directory RVA
- wrong IAT size
- absolute address patched as a raw RVA instead of an image-relative virtual address
- broken branch displacement
- section raw pointers not aligned to `0x200`

None of this is Brainfuck-specific. Replace the payload and the PE container rules stay the same.
